# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Chrome extension (Manifest V3, bring-your-own-key) that rewrites the paragraph being typed into fluent English, shown as a ghost-suggestion card below the field. Tab accepts, Esc dismisses. No server: requests go straight from the browser to the user-configured LLM endpoint.

## Commands

- `npm test` — vitest unit tests (covers the pure logic in `src/lib/` only)
- `npx vitest run tests/guards.test.js` — run a single test file
- `npm run smoke` — Playwright end-to-end: loads the real extension in Chromium against a mock SSE endpoint (`tests/smoke/extension.spec.js`). Needs `npx playwright install chromium` once.
- `npm run lint` / `npm run format:check` — ESLint / Prettier (both enforced in CI)
- `npm run pack` — zip `src/` for the Web Store
- Pre-commit hook (lint + unit tests): enable with `git config core.hooksPath .githooks`

CI (`.github/workflows/ci.yml`) runs lint, format:check, unit tests, then smoke.

## Architecture

**No build step.** `src/` loads unpacked as-is — plain JS, no bundler, no runtime npm dependencies. Keep it that way (ADR 0002).

Three Chrome contexts, sharing settings through `chrome.storage.local` (shape defined once in `src/lib/defaults.js`):

- `src/content.js` — classic (non-ESM) content script injected on all pages. Tracks the focused editable (input/textarea/contenteditable), debounces typing pauses, extracts the paragraph under the caret, applies trigger guards, and renders the ghost card inside a shadow DOM. It dynamic-imports shared code from `src/lib/` via `chrome.runtime.getURL` — this is why `lib/*.js` is listed in `web_accessible_resources`.
- `src/background.js` — MV3 service worker that owns **all network calls** (host_permissions bypass CORS there, so LLM requests must never move into the content script). Content scripts connect on the `'rewrite'` port: send `{ id, text }`, receive streamed `{ type: 'chunk'|'done'|'error', id }`. A new message on the same port aborts the in-flight request. A separate one-shot `{ type: 'test' }` runtime message serves the options page's "test connection".
- `src/options.js` / `options.html` — settings UI.

`src/llm/` holds two hand-written streaming clients (~40 lines each): `anthropic.js` (native Messages API, `/v1/messages`) and `openai-compat.js` (`/v1/chat/completions`). Deliberately no SDK and no routing Claude through OpenAI-compatible shims — see `docs/adr/0002`. Both share the pure SSE parser in `src/lib/sse.js`.

`src/lib/` is pure, browser-API-free logic and the only unit-tested code. New logic that can be pure should live there so it stays testable.

i18n: all user-facing strings go through `chrome.i18n` with catalogs in `src/_locales/{en,zh_TW}/messages.json`.

## Design invariants

- **Never auto-replace.** The field is untouched until the user presses Tab (ADR 0001: IME safety, and a human eye on every meaning change). Replacement goes through `document.execCommand('insertText')` — deprecated, but the only API that preserves the native undo stack; keep the `setRangeText` fallback behind it.
- **Errors in the typing flow are silent by design** — a dead endpoint must never interrupt writing. The options page "test connection" is the loud path for diagnostics.
- **Only the paragraph under the caret is sent** to the configured endpoint. No logging, no analytics; the API key stays in `chrome.storage.local`. PRIVACY.md and the store listing make these promises — changes must keep them true.
- Trigger guards live in `src/lib/guards.js`: min chars/words, mostly-English check (any CJK character in the paragraph blocks triggering), and dedup against the last suggested/accepted/dismissed text. `triggerBlockReason` returns a human-readable reason (logged when the `debugLog` setting is on); `Alt+R` in the content script bypasses all guards, the blocklist, and the master switch.
